> 来源文件:`~/Downloads/283224.rom`(A100-80G,MD5 已验);表在 282161.rom(GRID-32G)
> 中逐字节相同,两个镜像(0x40034 / 0xa0034)也逐字节相同 —— 数值可信。
>
> ⚠️ **重要前置**:v59 改的是 **CMP-10G 卡自己的 VBIOS(92.00.66.00.02,在服务器上,
> 本地没有)**。本清单的偏移来自 A100 ROM 的表;打上之前必须先取回 CMP ROM 并验证
> 同布局:检查 `*(u32*)(rom+0x4007c) == 0x38d4841b` 且 `*(u32*)(rom+0x4009c) ==
> 0x39268428`(镜像 0xa007c/0xa009c 同理)。若不符,按同样的"行基址 0x40034、
> 步长 0x40、16 dword/行"规则在 CMP ROM 上重新定位(值碰撞即可找到行)。

## 策略

FWSEC/devinit 解释器按 cert/fuse 选中 CMP 行内位置(运行值碰撞证明落在含 CMP 值的
下标上)。因此:**把行内所有"当前=CMP 值"的 dword 改写为 A100 p10 值**,
不论解释器选哪个下标,写出来的都是 A100 值。两个镜像(0x4xxxx 与 0xaxxxx)都改。

## MAC 校验区标注

PCI 镜像在文件 0x5e00 与 0x65e00;MAC 校验区为镜像相对 0x2200–0x43A00
(表在镜像相对 0x3a234 起)。**全部补丁偏移都在 MAC 校验区内** —— 这就是 v59 的赌注:
赌 GSP 期 FWSEC 不对 host 上传镜像做 MAC 重验(power-on 已验过)。
若 boot 报 `NV_UDE_ERR_VBIOS_VERIF_*` / DEVINIT_TABLE_AUTHENTICATE 类错误 = 被拦。

## 备选/最后手段:0x9a02a0 CONFIG4(row 4)

运行时被写保护(B6),host 写不进;表补丁是唯一可能改它的途径。
但 CMP 值 0xc4030033 占行内 15/16 下标,blanket 改 = 所有分区都拿 idx10 值
0xc4020033,语义变化大(A100 只有 p10 用它)。**与主清单分开,单独一轮试。**
```
0x40134..0x40170 步 4,共 15 项(idx0-9,11-15)+ 镜像 0xa0134..0xa0170
0xc4030033 -> 0xc4020033
```
(idx10=0xc4020033 本就在,不动。)
