# 问题陈述：80G 解锁后的「32G 墙」

> 记录日期：2026-08-08  
> 状态：根因已定性；host 侧绕行已否；目标是**两侧显存都能安全读写**，不是守住洞下半边。

相关长文：`docs/HANDOFF_20260808_NIGHT.md`、`docs/RESEARCH_REPORT_20260808.md`。

---

## 1. 我们要解决什么

CMP 170HX（`0x2082`）经 open driver `610.43.02` 解锁到约 **80G** 后，必须能**同时安全使用洞下与洞上**的用户显存。

**只使用洞下（≲~35G）没有解锁意义**——那约等于退回「略小于 40G 连续区」的用法；高位半边是毒区，还会污染低位。

验收（缺一不可）：

1. 真冷启动后 `vec_scan2 48` 全绿（`total_bad_units=0`）。
2. 双进程：一侧主要落在洞下、一侧主要落在洞上，同时推理/写压，互不破坏。
3. （产品）llama 等大上下文越过 ~40G 仍连贯。

---

## 2. 现象（已实锤）

- 单进程 GPU 映射总量 ≳~35G，且对象物理页被幻影洞 **`[36G, 44G)`** 切成 **≥2 段** 时：
  - VA `x` 与 VA `x+32G` **翻译混叠**（读 `x` 得到 `x+32G` 的内容）。
  - 偏移精确 **+32G**（PA bit35 / 2MB 页索引 bit14）。
- **单段对象免疫**，即便整体 PA 在 60G+（E1）。
- 客户端页表**完全由 GSP 构建**；host MAP RPC 只传句柄。

俗称「32G 墙」：**混叠周期是 32G**，不是「只能用到 32G」；爆发点是开始用到洞上物理页。

---

## 3. 为什么 40G 路径没有墙、80G 有

| | 40G profile | 80G unlock |
|---|---|---|
| 用户堆 | 连续，无中洞 | 中段出现 GSP 页表/元数据幻影带（~37–40G） |
| host 对策 | — | PMA pin 挖洞 `[36G,44G)`，避免用户踩死 GSP |
| 大对象 | 永远单段 | 易被洞切成 ≥2 段 |
| GSP 行为 | 不进入（或不伤害）多段错误路径 | 处理 **seg2（洞上）** 时多写一份 PTE 到 **−32G 低位槽** |

要点：

- **不是**「没有 40G 以上寻址所以高位写不进」。高位主路径是通的（单段高位 OK；洞上进程自己可正常生成）。
- **是**「高位/seg2 写对了，又多写进低位一份」。
- 40G 下用户 PA 的 bit35 基本为 0，且无洞 → 双写逻辑进不去或清 bit 后仍是同一槽（no-op）。

---

## 4. 双进程左右分立（2026-08-08 夜实测）

几何容量（洞 `[36G,44G)`）：

- 左（洞下）≈ **35.7G**
- 右（洞上）≈ **35G**

实测：

1. 先起左：Q8_0 ≈ **26.7G**（总占用贴到 ~34G）→ **单独正常**。
2. 再起右：Q6_K ≈ **20.9G**（左边仅剩 ~2G，大块只能上洞上）→ **右正常**。
3. 右加载完成后，左立刻变成 `////////////////` 类垃圾输出。

结论：**左右各跑一个进程不能当 workaround**。洞上进程一建页表/写高位，低位侧被连坐——与「高位多写到低位」同一类问题。

---

## 5. 已否路径（不要再空转）

- 改共享 `fbRegionInfo` 把低部标 reserved「挤」GSP 到尾部 → host PMA 饿死 / Ampere「>2 不连续 reserved」断言；host reopen+merge 后几何回到基线，**并不移动 GSP 池**。
- regkey（`RMEnablePmaManagedPtables=0`、加大 GSP heap 等）→ 只**挪**幻影，不消混叠。
- 落盘改 `gsp_tu10x.bin` → Booter 验签失败（如 `0xb`）；WPR 经 PRAMIN 不可靠改写；debug fuse 生产锁定。
- 应用层「只守洞下 / 单进程 ≤30G」→ **不满足产品目标**（等于放弃 80G 解锁价值）。

---

## 6. 可能的终局（仅此两类）

### A. 修双写（正道）

在 **`gsp_tu10x`**（GA100 实载固件，不是 `gsp_ga10x`）中，定位多段 PTE 槽位计算，**去掉或修正 −32G 二次写**。

- 洞可暂留，两侧即可用。
- 卡点：**补丁注入通道**（验签 / Booter / 非 WPR 可写窗口）+ tu10x 地标重定位。

### B. 消灭分段触发（依赖 E1 始终成立）

把 GSP 池迁出用户中段 → 去掉中洞 → 大对象单段铺满 ~80G。

- 若存在「与分段无关、仅 PA≥阈值仍双写」，B 不够，必须回 A。
- 池迁移本身也多半要动 GSP 侧，与 A 共享注入能力。

---

## 7. 当前决策

1. **目标锁定**：两侧都能用；单边可用不算成功。  
2. **主攻**：GSP tu10x 补丁（终局 A）+ 注入/验签突破；并行准备地标与最小补丁字节。  
3. **停做**：以 host region 图、左右进程、只守洞下冒充解法。  
4. **固件文件**：一律以 `gsp_tu10x.bin` / `gsp_rm_tu10x.elf` 为准（GA100 → TU10X 分支）。

---

## 8. 一句话

80G 解锁造出中洞 → 多分段 → GSP 对洞上段 PTE **多写一份到低 32G 槽** → 低位被毁，高位也不能安全用。  
40G 无洞故无墙。  
**要解锁两边，必须改 GSP（禁双写和/或迁池去洞），不能只在 host 侧挖洞或限容量。**
